# Visual hover contract

Module src/previews.js, CommonJS, Node18+, no external or VS Code dependencies.

Exports:
- enrichPreviewItems(text,documentPath,resolvedItems): return array preserving each existing resolved occurrence, adding contextProperty and literal/aggregate occurrences for hover. No mutation. Use parseFile from ./tokens; its expressions entries now include property (array of property path parts), node AST and scope. Each token group supplies name/properties. Existing items stay first so resolved calls/refs take priority. New numbers, lengths, strings, lists/maps are only actual expression AST positions; never comments/keys/annotations/import/source names. Quoted/unsupported expressions skipped. Aggregate lists/maps only if child values are statically resolved. Token file literals should receive reference group.member, layers property path. Each output has start,end,reference,value,color?,definition?,contextProperty?.
- createVisualPreview(item,{isDark=true}={}): return {kind,alt,svg,width,height} or undefined. Kinds colour, radius, spacing, font-size, line-height, letter-spacing, font-family, font-weight, value. Width320, sensible bounded height. A safe generic value card is allowed for otherwise resolved values. This visual is illustrative and bounded, not a full Elyx renderer.

Classify from colour data first, then normalized reference/contextProperty and definition path. radius/radii/corner-radius -> radius; spacing/space/gap/padding/margin -> spacing; fontSize/font-size -> font-size; fonts/font-family -> font-family; lineHeight/line-height/leading -> line-height; letterSpacing/letter-spacing -> letter-spacing; fontWeight/font-weight -> font-weight; generic values otherwise. Do not mistake fontSize for generic size or lineHeight for spacing.

Official Elyx schema: frame.corner-radius pixels, scalar or [topLeft,topRight,bottomRight,bottomLeft]; text.line-height positive unitless multiplier, 0 automatic; text.letter-spacing percent of font size. Bare pixel values in radius/spacing/font-size families use pixels. Other unknown units render a generic labelled value rather than guessed dimensions. Oversized samples scale/clamp and label the scale. Radius9999 is a pill at preview box size. Negative radius should not produce a fake valid radius. Show alpha using checkerboard. Text in SVG escaped including labels/font-family strings, no external resources/scripts/foreignObject. Colours derive strictly from numeric normalized channels and palette constants. Theme colours chosen for legibility in light/dark. Rendering never edits files or executes source.

The adapter converts svg to an image URI for MarkdownString and adds it above existing resolved value/source text. Hovers remain untrusted, no command links or scripts. Resolver semantics unchanged. This feature must cover literal values in token files as well as imported references. Tests use Bun and actual VS Code/VSCodium hover providers. Full compiler/theme/variant evaluation remains out of scope.

Selection: enriched items include hoverRanges [{start,end}], which cover real AST value leaves and opening/closing delimiters. They exclude map keys, named argument names, comments and whitespace. Full start/end spans stay unchanged. findPreviewItem(items,offset) is exported and used by the adapter to apply both span and hoverRanges. Original resolved calls receive AST ranges too, so a comment inside a call cannot trigger its card.
